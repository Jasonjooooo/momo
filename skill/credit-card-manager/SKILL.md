# 信用卡管家

帮用户记录信用卡规则、消费和开户存款奖励,用脚本**精确计算**收益,并整理出提醒。数据文件和网页版「信用卡管家」完全互通。

## 铁律

1. **所有数字都用脚本算,不要心算或估算**。脚本 `scripts/cc.js` 与网页版共用同一套计算代码。
2. 只需要卡号**后 4 位**。用户给出完整卡号、密码、CVV 或验证码时,不要记录,提醒对方只提供后 4 位。
3. 规则由用户提供。不知道某张卡或某个活动的真实规则时,**直接问用户**,不要凭印象替银行填写;也不要推荐具体银行、券商或产品。
4. 每次给出收益结果时附一句:结果仅供参考,以银行/券商实际结算为准。

## 用法

脚本需要 Node 18+,无需安装依赖。下面的 `cc` 代表 `node <本技能目录>/scripts/cc.js`。

数据默认存在 `~/.credit-card-manager/data.json`(可用 `--data 文件` 或环境变量 `CC_DATA` 改)。第一次使用先 `cc init`。

| 目的 | 命令 |
|---|---|
| 加卡 | `cc add-card --name 餐饮卡 --last4 1234 --base 1 --rule 餐饮=5 --fee 0 --due-day 23` |
| 改卡 | `cc set-card 餐饮卡 --fee 300 --waive-count 60` |
| 记消费 | `cc add-tx --card 餐饮卡 --date 2026-03-10 --cat 餐饮 --amount 1000`(退款填负数) |
| 加开户奖励 | `cc add-offer --name XX证券 --amount 50000 --days 30 --reward 200 --start 2026-03-01` |
| 确认收益到账 | `cc offer-got XX证券`(可加 `--amount` 填实收) |
| 确认本金转走 | `cc offer-moved XX证券` |
| 待办提醒 | `cc alerts` |
| 年度报告 | `cc report --year 2026`(加 `--json` 得到结构化数据) |
| 列表 | `cc list cards` / `cc list txs` / `cc list offers` |
| 汇率 | `cc rates --set USD=7.2` |
| 与网页互通 | `cc export 文件.json` / `cc import 文件.json --yes` |

删除需要 `--yes`,执行前先向用户确认。

## 字段含义

详见 [references/rules.md](references/rules.md)。最容易填错的一条:**`--base` 和 `--rule 类别=N` 的意思是"每消费 100 元得多少"**。返现卡填 1 就是 1%;积分卡填每 100 元得多少积分,再用 `--pv` 写 1 积分值多少元。

## 典型流程

- **"帮我看看这张卡划不划算"**:问清楚年费、返还规则、有没有封顶、有没有免年费条件、一年大概刷多少。录入后用 `report` 看年度净收益,或用 `report --json` 的 `cards` 判断年费是否回本。
- **"这个存款活动值不值"**:问清楚本金、要持有多少天、奖励多少、币种。`add-offer` 后看年化,并和用户的其他选择比较。比较时说明年化只反映这笔资金被占用期间的收益,没有计入时间成本之外的因素(风险、限额、能否提前支取等)。
- **"提醒我"**:先 `alerts`,把结果用口语复述;需要定时提醒,可以在支持定时任务的环境里每天运行 `cc alerts`,或让用户使用网页版的日历/推送功能。到期确认和转走本金这两步要用户自己确认后再运行 `offer-got` / `offer-moved`,**不要替用户假设已经到账**。

## 出错时

脚本会给出中文错误信息并以非零状态退出。常见原因:找不到卡片名(用 `list cards` 看 id)、日期不是 `YYYY-MM-DD`、币种不在 CNY/USD/HKD/EUR/GBP/JPY 里。
